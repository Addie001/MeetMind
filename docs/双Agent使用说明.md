# 双 Agent：做什么、为什么、怎么用

一个角色先提取行动，另一个角色阅读完整转写核验。发现字段问题后，反馈给提取角色最多修正一次，再核验。仍有疑问保留候选并标记人工重点审查，避免无限循环、增加费用。

这是有界多角色工作流，不是任意工具自主执行的Agent群。核验角色不能访问gold或滴答写入工具。

## 运行路径

提取 → 核验 → 通过则结束；字段待修正则修正一次 → 再核验 → 人工确认。

- 非工作、已撤回等明确不成立项建议排除，最终核验直接排除的候选及理由保存在rejected_actions，页面可查看；修正前的原候选、排除理由及各阶段结果保存在agent_history供复盘。
- 未确定项保留，不以证据不足为由悄悄删除有效任务。
- 核验超时、无效JSON、行动ID缺失/重复、伪造引用等均回到人工审查，不假装通过。
- 空候选不再调用核验模型；只有排除项时不花额外调用重写空列表。
- 原V1负责人校验保持不变；修正结果允许用原文明确应答作为负责人依据，但仍需再次语义核验。

## 启用

在本地 .env 设置 `MEETMIND_ANALYSIS_MODE=dual`，重启服务；默认single维持原版。仅新分析使用该配置，不重写已有人工审核或同步记录。核验不代替人工确认，滴答写入的pending/synced/uncertain边界保持不变。

生产入口为server.workflow → durable_agents.analyze → agents子图。外层图保留人工确认边界，子图独立保存节点检查点于meetmind.sqlite3.agents；输入/模型/实现版本变化不会复用旧断点。中断时已成功节点的结果可恢复，模型请求与检查点之间仍可能产生重发，不宣称exactly-once。

## 如何比较

实验使用evaluation/data/frozen/v1固定输入。对照组复用第一次提取结果，再增加核验和修正，隔离提取随机性；费用/耗时统计加回原提取成本。Gold只用于离线裁定，不能喂给提取或核验模型。

每轮目录保存源码指纹、预测、节点审查历史和评分。初标与本次评分均为Agent裁定，需独立人工复核；开发集高分不等于泛化能力。
