# 😇开发集

### 🎬 腾讯会议录制脚本（共 6 场）

#### 🎯 脚本 1：双人短会（高清晰度 / 研发执行）

- 主题：线上 Bug 紧急修复与日常排期

- 角色：老李（Leader）、小李（开发）

- 测试点：验证短文本、指令清晰场景下的 100% 提取准确率，测试相对日期（“今天下班”、“明天”）的解析。

```Plain Text
[00:00:10] 老李: 小李，咱们直接开始。昨天说的那个“登录验证码发不出去”的 Bug，今天能修好吗？
[00:00:22] 小李: 李哥，查到了，是第三方短信网关的接口超时导致的。我今天上午改一下重试机制，今天下班前肯定能提测。
[00:00:35] 老李: 行。另外那个新用户注册界面的 UI，产品觉得太丑了，让你按照最新设计稿改一下。
[00:00:45] 小李: 那个设计稿我看了，改动挺大的，今天肯定弄不完。
[00:00:52] 老李: 没关系，那个不急，你明天下午弄完就行。今天重点把验证码 Bug 搞定。
[00:01:00] 小李: 好的没问题。
```

#### 🎯 脚本 2：双人短会（条件依赖 / 外部卡点）

- 主题：与外部供应商对接沟通

- 角色：老李（项目经理）、小李（技术接口人，为了满足“两人必须含老李和小李”，此处将老段的工作转给小李）

- 测试点：测试模型能否识别出“带有条件限制的行动项”，并将其准确写入 `acceptance_criteria`（验收标准）。

```Plain Text
[00:00:05] 老李: 小李，腾讯会议那个 API 对接得怎么样了？
[00:00:12] 小李: 接口联调通了，但是现在拉取不到用户的转写数据，一直报 403 权限错误。
[00:00:22] 老李: 那去问腾讯那边了吗？
[00:00:26] 小李: 问了，他们说我们的企业资质还在审核，大概后天才能通过。
[00:00:35] 老李: 行，那你先别干等着。趁着这两天，你把前端的 UI 交互先自己写个 Mock 数据调通了。
[00:00:45] 小李: 行，我今天下午先把 Mock 调通。
[00:00:50] 老李: 等后天资质下来，你第一时间换上真实接口跑一次，确认没问题了，通知老谢来测。
[00:01:02] 小李: 知道了，资质一过我就跑真实数据。
```

#### 🎯 脚本 3：三人会议（甩锅大会 / 跨部门同步）

- 主题：上线前夜的风险排查会（老段参与）

- 角色：老李（主持）、小李（前端）、老段（后端）

- 测试点：从“扯皮”中提取有效结论。有很多无效的推诿，最后被强制压下来的任务。

```Plain Text
[00:00:05] 老李: 明天就要上线了，现在还有什么风险？大家过一遍。
[00:00:12] 小李: 我这边问题很大。昨天发现页面在 Safari 浏览器上样式全乱了，根本测不下去。
[00:00:22] 老段: 那是你前端没做好适配，跟我有什么关系？
[00:00:30] 小李: 怎么没关系？你后端返回的字段太长，把表格撑爆了，我才没法适配的。
[00:00:38] 老段: 你不会加个省略号截断吗？
[00:00:45] 老李: 停！别吵。小李，你现在就加一个 CSS 截断，要多久？
[00:00:52] 小李: 改代码只要 5 分钟，但发版要等 1 个小时。
[00:00:58] 老李: 那就现在改，马上发。老段，支付回调的接口经常延迟，有时候要 10 秒才返回，你去查一下。
[00:01:10] 老段: 这个是第三方接口的问题，我改不了。
[00:01:15] 老李: 你去跟第三方对接，问清楚是不是网络问题，今天下午 6 点前要给我个说法。如果实在延迟，让小李在前端加个“处理中”的提示。
[00:01:28] 小李: 提示我可以加，我等老段的结论，他确认了我再改。
[00:01:35] 老李: 行，那今天下班前：小李搞定 CSS 截断，老段查明支付延迟原因。散会。
```

#### 🎯 脚本 4：三人会议（商业需求确认 / 销售与产研）

- 主题：大客户定制化需求确认（老谢参与）

- 角色：老李（主持）、小李（研发）、老谢（销售）

- 测试点：测试非技术背景（销售）与技术人员沟通时，模型能否抽象出“验收标准”和“具体任务”。

```Plain Text
[00:00:05] 老李: 老谢，那个国企的大客户，到底要什么定制化功能？
[00:00:12] 老谢: 他们老板有要求，导出的 PDF 报告里，必须要有公司的红头文件和公章。
[00:00:22] 小李: 公章？这不可能啊，我们怎么知道他们的公章长什么样？
[00:00:30] 老谢: 他们的意思是，在后台自己上传公章图片，然后导出的时候自动盖上去。
[00:00:40] 小李: 技术上可以实现，但是排版会非常恶心，还要调坐标。
[00:00:48] 老李: 小李，这个功能能评估一下工作量吗？客户催得很急，最好这周末能出个能演示的 Demo。
[00:01:00] 小李: 这周末？我今天晚上加班画个页面出来吧。但这只是个壳子，坐标可能对不准。
[00:01:10] 老李: 壳子也行。老谢，你拿到小李的 Demo 后，明天发给客户看，告诉他们这只是初版，让他们先看排版位置对不对。
[00:01:22] 老谢: 好的，我明天中午前发给他们。
[00:01:28] 老李: 那就这样，小李今晚出 Demo，老谢明天发给客户。如果客户确认了，小李下周二把真正的盖章功能写进代码。
[00:01:40] 小李: 没问题。
```

#### 🎯 脚本 5：四人长会（低清晰度 / 头脑风暴防幻觉）

- 主题：下季度产品创新方向探讨

- 角色：老李、小李、老段、老谢

- 测试点：防幻觉。全场没有具体时间点，没有明确负责人，全是“回头想想”、“我觉得可以”。看看模型会不会强行瞎编。

```Plain Text
[00:00:05] 老李: 大家放开聊聊，下个季度，咱们这款产品还能加点什么新功能？不用太保守，发散一下。
[00:00:15] 小李: 我觉得可以搞个移动端 App，现在大家开会都带手机，如果有 App 肯定方便。
[00:00:25] 老段: 搞 App 成本太高了吧，前端又得招人。我觉得不如搞个微信小程序，直接嵌入。
[00:00:35] 老李: 小程序这个方向可以考虑，老段，回头你调研一下小程序接入的难度，写个报告啥的。
[00:00:45] 老段: 行，我下周抽空看看吧，不一定有时间。
[00:00:52] 老谢: 其实我觉得现在最缺的是数据分析。咱们连用户到底看了多久的摘要都不知道。
[00:01:05] 老李: 对，数据埋点这块确实很重要。老谢你懂这块，要不你来牵头搞个数据漏斗？
[00:01:15] 老谢: 我懂是懂，但我手头测试任务太多了。得等这个月版本发完才有空。
[00:01:25] 老李: 没事，这就先作为一个备选方案，后面再说。小李，前端在用户体验上有什么想法？
[00:01:35] 小李: 我之前想过，能不能加个语音播报功能？把会议摘要直接读出来，这样大家走路的时候也能听。
[00:01:45] 老段: 浏览器自带的 TTS 不就能读吗，干嘛还要单独做？
[00:01:52] 小李: 自带的太难听了，而且没感情。
[00:02:00] 老李: 语音这个先放一放。总而言之，小程序和数据埋点，你们几个回头各自琢磨琢磨，也不急着定。今天先这样吧，大家去忙吧。
```

#### 🎯 脚本 6：四人长会（高复杂度 / 需求品审 / 长文本）

- 主题：V2\.0 新功能（AI 智能摘要）方案评审

- 角色：老李、小李、老段、老谢

- 测试点：长文本不丢信息。测试需求被砍、多线并发、责任交接。包含明显的“推诿”和“最终拍板”。

```Plain Text
[00:00:10] 老李: 大家都到齐了，咱们过一下 V2.0 的 AI 智能摘要需求。这个功能下个月初必须上线。老段，你先把技术方案说一下吧。
[00:00:25] 老段: 目前的想法是用大模型直接做总结。但是有两个问题，一是速度慢，处理一场一小时的会议大概要 30 秒。二是太费 Token 了，成本很高。

[00:01:20] 老李: 加缓存没问题，这周五能把缓存搞完吗？
[00:01:28] 老段: 周五够呛。我这周还要搞那个 Bug 修复，最快也得下周一。
[00:01:38] 老李: 那这样，V2.0 的第一期，咱们先不上真正的 AI 大模型，先用正则规则提取简单的行动项，这样成本低，速度也快。
[00:01:52] 小李: 对，先上规则的，界面我两天就能画完。
[00:02:00] 老谢: 等等，如果先用正则，那怎么提取复杂的任务？测试的时候怎么做断言？
[00:02:12] 老段: 测试的时候，我提供一份固定格式的 Mock 文本，老谢你直接用那个测就行，只要保证不报错。
[00:02:20] 老李: 好，老段，你今天下班前把那份 Mock 文本发给老谢。
[00:02:28] 老段: 好，我傍晚发。
[00:02:35] 老谢: 行，我拿到文本后，这周四把核心的边界条件测一遍。
[00:02:42] 老李: 对了，流式输出的动画，小李你什么时候能给我看？
[00:02:48] 小李: 我明天下午下班前把 Demo 发你。
[00:02:55] 老李: 好，总结一下：老段今天发 Mock 文本，下周一加完 Redis 缓存；小李明天给流式动画 Demo，两天内画完规则提取的界面；老谢周四跑核心测试。没别的问题就散会。
```

### 🎬 腾讯会议录制脚本（共2场）

#### 🎯脚本 7：三人会议（同名人员 \+ 跨段指代 \+ 证据矛盾）

- 主题：跨团队联调排期确认

- 角色：老李（主持）、小李（前端）、小王（后端，两人同名，分属不同模块）

- 测试点：

    - 同一会议出现两个"小王"，模型能否用"前端小王/后端小王"或上下文区分 owner，而不是笼统写"小王"

    - 跨段指代："那个接口""上次说的那个"需要回指前文才能确定行动项

    - 证据矛盾：先说"周三交"，后文改成"周五"，核验 Agent 应识别为"变更"而非两条独立行动项

    ```Plain Text
    [00:00:05] 老李：今天对一下联调排期。前端小王，登录页改版你那块怎么样了？
    [00:00:14] 小王（前端）：登录页 UI 已经改完了，但是等后端接口字段确认才能联调。
    [00:00:25] 老李：后端小王，字段文档什么时候能给？
    [00:00:32] 小王（后端）：字段文档我周三能给初版，但完整版要等产品确认，可能周五。
    [00:00:44] 老李：那先给初版。前端小王，你拿到初版先联调，别等完整版。
    [00:00:55] 小王（前端）：行，我周三拿到就联调。
    [00:01:05] 老李：另外上次说的那个导出接口，后端小王你还没动吧？
    [00:01:14] 小王（后端）：导出接口我这周排不进去，得下周一。
    [00:01:22] 老李：下周一太晚了。这样，你周三先把字段文档给出来，导出接口挪到下周三，中间先把联调跑通。
    [00:01:36] 小王（后端）：好，字段文档周三，导出接口下周三。
    [00:01:44] 老李：前端小王，导出接口挪到下周三，你联调排期也顺延，别卡在这。
    [00:01:54] 小王（前端）：明白，我按新排期走。
    [00:02:00] 老李：散会。
    ```

#### 🎯脚本 8：三人会议（负责人模糊 \+ 条件承诺 \+ 无明确日期）

- 主题：客户投诉处理分工

- 角色：老李（主持）、小李（研发）、老谢（销售）

- 测试点：

    - 负责人始终没说清："得有人去对接""你们谁方便"——模型应留空标"待确认"，不编造

    - 条件承诺："如果客户坚持要，再考虑"——不是确定行动项，核验应判"证据不足/条件性"

    - 无明确日期："尽快""这两天"——不应编造具体日期

```Plain Text
[00:00:05] 老李：国企那个客户投诉了，说导出报告格式不对。这事得有人去对接一下。
[00:00:16] 老谢：我这边在跟，但技术细节我说不清，得研发配合。
[00:00:24] 老李：小李，你配合老谢去对接一下？
[00:00:30] 小李：我这周手上三个需求，实在排不开。你们谁方便谁去？
[00:00:40] 老李：那这样，老谢你先跟客户约个时间，技术细节到时候再说。
[00:00:50] 老谢：约时间可以，但我这两天在外地出差，得回来再说。
[00:01:00] 老李：行，你回来尽快约。小李，如果客户坚持要改格式，你再考虑出个方案。
[00:01:12] 小李：如果真要坚持改，那我再排期吧，现在说不准。
[00:01:20] 老李：好，先这样，老谢回来对接，具体技术方案看客户态度。
[00:01:30] 老谢：行。
```

```Plain Text
[09:35] 老谢：客户那边我本来约了明天演示，要不要取消？
[09:42] 老李：演示取消，跟客户说延期，具体时间待定。
[09:50] 老谢：好，我去说。
[09:58] 小李：那文档我还写吗？
[10:05] 老李：文档照写，这个不影响。
[10:12] 小李：行，我继续写。
```
