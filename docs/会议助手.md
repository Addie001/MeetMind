# 会议助手

### 对齐后的第一版功能清单

## 一、第一版功能清单（已确认）

产品定位：从一场会议中提取可验证的行动项，经人工确认后写入滴答清单。

核心原则：证据可追溯优先于摘要流畅，人工确认优先于自动执行。

### 会议接入与触发

- 通过腾讯会议 MCP 拉取会议列表（主题、时间、时长、参会人、分析状态）。

- 用户手动选择某场会议，触发分析。

- 不做：自动分析、实时音频接入。

### 分析输入

- 使用腾讯会议的转写文本（含段落 ID、时间戳、发言人标识）作为输入。

- 不使用元宝纪要等已摘要化的二手信息。

### 分析流水线（后台处理）

- 议题切分。

- 行动项提取，每条行动项必须附带原文引用（发言人 \+ 时间戳 \+ 原句）。

- 行动项按议题分组，独立携带负责人、截止时间、验收标准字段。

- 负责人无法从发言中明确判断时，留空并标记“待确认”，不编造。

- 不做：争议识别、决策核验、信息缺口发现。

### 报告页面

- 一句话总结。

- 按议题分组的行动项清单。

- 每条行动项旁有“查看原文”入口，点击定位到转写对应片段（发言人、时间戳、原始语句）。

- 结论与证据分离但可关联。

- 不做：争议清单、风险清单、完整管理者摘要、讨论脉络展开。

### 行动确认环节（Human\-in\-the\-loop）

- 用户逐条确认、修改或删除行动项。

- 确认或补全负责人、截止时间、验收标准。

- 勾选需要同步到滴答清单的条目，选择目标清单。

- 确认后调用滴答清单 MCP/API 写入，成为真正的待办任务。

- 不做：生成追问、追问审批发送。

### 滴答清单写入

- 调用现成滴答清单 MCP（如基于官方 OAuth 2\.0 的实现）创建任务。

- 不做：自建任务看板作为主要方案（仅保留为演示备选）。

### 跨会议追踪（仅预留，不实现）

- 数据模型中预留 `project_id` 和行动项状态字段。

- 第一版不实现：项目视图、承诺漂移可视化、历史行动项对比。

### 明确的产品边界

- 不追求实时处理。

- 不覆盖所有会议类型，聚焦项目周会和方案评审会。

- 以文本转写为输入起点，不做实时音频和官方深度集成。

- 滴答清单为首选落地工具，自建看板不作主要工作量。

## 二、技术栈总览

| 层级 | 选型 | 用途 |
| :--- | :--- | :--- |
| 编排框架 | LangGraph（StateGraph + 条件路由 + interrupt_before） | 串联“拉转写 → 提取行动项 → 人工确认 → 写入滴答清单”全流程 |
| 输入源 | 腾讯会议 MCP `get_transcripts_details` | 获取带段落 ID、时间戳、发言人标识的结构化转写文本 |
| 提取能力 | 自有模型提取器 | 从原始转写中提取按议题分组的行动项，并校验原文段落引用 |
| 输出目标 | 滴答清单 MCP（官方 OAuth 2.0 方案） | 将用户确认后的行动项写入滴答清单，成为真实待办任务 |
| 人工确认 | LangGraph `interrupt_before` | 在写入滴答清单前暂停，让用户逐条确认/修改/删除 |
| 可观测性 | LangSmith Tracing | 调试多节点流程、追踪每步 token 消耗与延迟 |

## 三、核心资源链接

### 腾讯会议 MCP（输入源）

Token 获取：[https://meeting\.tencent\.com/ai\-skill](https://meeting.tencent.com/ai-skill) 

MCP 官方说明：[https://meeting\.tencent\.com/support/topic/2233/index\.html](https://meeting.tencent.com/support/topic/2233/index.html)

关键工具（你第一版只用这一个）：

- `get_transcripts_details`：查询转写详情 

- 注意：不要用 `get_smart_minutes`，元宝纪要不含原文位置信息，无法支撑证据追溯

调用链路（来自 MCP 工具参考）：

1. 若只有会议号（9 位数字），先调 `get_meeting_by_code` 拿 `meeting_id`

2. 调 `get_records_list` 拿 `record_file_id`

3. 调 `get_transcripts_details` 拿转写内容（支持 `pid` 分页）

备选（REST API，MCP 受限时用）：[https://cloud\.tencent\.com\.cn/document/product/1095/42407](https://cloud.tencent.com.cn/document/product/1095/42407)

- 录制管理下包含转写详情、转写段落、搜索转写等接口 

### 滴答清单 MCP（输出目标）

推荐方案：`GalaxyXieyu/didatodolist-mcp`

- GitHub：[https://github\.com/GalaxyXieyu/didatodolist\-mcp](https://github.com/GalaxyXieyu/didatodolist-mcp)

- PyPI：`iflow-mcp_galaxyxieyu-didatodolist`

- 已从逆向接口切换到官方 OAuth 2\.0 \+ Open API，全面对齐 `/open/v1` 端点 

- 支持创建任务：`POST /open/v1/task` 

官方开放平台（自行封装时参考）：[https://developer\.dida365\.com/docs\#/openapi](https://developer.dida365.com/docs#/openapi)

- 注册应用 → 获取 `Client ID` / `Client Secret` → 配置 OAuth Redirect URL → 完成授权

### LangGraph 相关

核心机制：

- `add_conditional_edges`：根据 State 决定下一步走向（如“有行动项待确认 → 进入人工确认节点”）

- `interrupt_before`：在指定节点前暂停，等用户操作后继续

Supervisor 参考（如果你想把流程拆得更细）：`langgraph-supervisor` 库，提供基于工具的 agent 交接和灵活的消息历史管理 

可观测性（调试用）：LangSmith

- 文档：[https://docs\.langchain\.com/langsmith/observability](https://docs.langchain.com/langsmith/observability)

- 可追踪每个节点的输入输出、token 消耗、延迟，调试多节点流程时很有用 

### 会议分析骨架（供改造参考，非直接依赖）

`ffiruzi/ai-meeting-minutes`：LangGraph 多 Agent 会议分析流水线，可提取行动项（含负责人、截止日期）。用作理解“会议转写 → 行动项”的流程设计参考，但它的 State 设计不包含你需要的证据追溯字段，需要改造。

## 四、第一版技术决策备忘

1. 分析输入固定为转写：只调 `get_transcripts_details`，不碰 `get_smart_minutes`。

2. 行动项按议题分组，每条独立携带 `owner`、`due_date`、`acceptance_criteria`、`evidence_ref`（原文段落 ID \+ 时间戳）。

3. 负责人无法判断时留空标“待确认”，不编造。

4. 写入滴答清单前必须经过人工确认节点（`interrupt_before`）。

5. 跨会议追踪第一版只预留字段（`project_id`、行动项状态），不实现项目视图。
