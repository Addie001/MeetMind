# 单 Agent 开发集基线：Agent 裁定 v1

本报告基于用户授权的 Agent 逐条裁定，不是人工 golden set 的最终评测。初标仍待人工复核；本次只审核9份开发输入，3份保留测试预测未用于质量分析。冻结数据、gold、原始预测和模型 prompt 均未修改；原始审核模板另存 review-templates/。

## 开发集指标

| 指标 | 结果 | 分母与含义 |
| --- | --- | --- |
| 行动项 precision | 90.91% | 20个匹配 / 22个预测 |
| 行动项 recall | 100% | 20个匹配 / 20个初标行动 |
| F1 | 95.24% | 2×20 / (22+20) |
| 证据支持率 | 95.45% | 21个得到支持的完整结论 / 22个预测 |
| 不支持率 | 4.55% | 1个存在无依据日期的结论 / 22个预测 |
| 负责人严格匹配 | 75% | 15/20；其中1条为合理昵称/角色别名差异 |
| 截止日期严格匹配 | 90% | 18/20 |
| 验收标准严格匹配 | 20% | 4/20；该数字不代表语义正确率 |

行动匹配按任务语义，与字段错误分开：错误日期不把整条行动再计一次FP/FN。证据支持与工作范围也分开：闲聊中的取外卖有原文支持，仍是不该输出的工作行动。负责人或日期留空属于缺失，没有产生无依据断言，证据支持可为true；缺失由字段指标反映。

## 错误定位

1. **范围外误提2条**：text-02输出点外卖、取外卖。原文真实，属于任务边界错误，不是捏造。V1 prompt 没有明确“只提工作行动”的产品范围，后续需将其作为独立prompt基线对照，不能全归功于新增核验Agent。
2. **无依据截止日1条**：tencent-02将预计后天审批通过映射为确定的2026-11-06行动截止日。任务及条件真实，但预计触发时间不等于交付截止日。这是核验需要重点覆盖的错误。
3. **负责人漏填4条**：tencent-01的UI、tencent-03的CSS及处理中提示、tencent-04的真实盖章实现。需跨段识别明确分派及回应。当前产物是经过validate_report后的输出；没有保存模型原始响应，不能断言空值一定出自模型而不是后端校验清空。
4. **负责人别名严格不一致1条**：tencent-06的Redis行动，预测实际昵称“早该睡觉了”，初标“老段”。本场可建立对应关系，不能当作语义负责人幻觉。若只排除这一字符串差异，语义上合理的负责人是16/20，但这只是诊断计数，不替换冻结严格指标。
5. **日期漏填1条**：text-03的数据交付“周三前”未输出日期，冻结日期锚为周三当天。原始非标准格式不改写，解析与模型理解需分别排查。
6. **验收字段的低精确匹配主要不具有语义解释力**：V1常将任务重述、交付时间、条件写入acceptance_criteria，而gold只记录独立验收要求。不能据20%宣称80%验收标准幻觉；在下一版指标中引入独立人工/Agent语义字段裁定后才能下结论。不得事后改v1 gold来提高分数。

无漏提是相对于本次20条初标和一对一粒度规则的结果，不代表其他会议中召回率100%。其中tencent-02的验证后通知按一条交付链计数，比较版本必须沿用同一粒度。

## 后续实验建议

先保持本次冻结模型输出作为V1对照，不立即改写。再分别比较：

- 单Agent原prompt（当前基线）。
- 单Agent明确工作范围等prompt改进，用来隔离prompt带来的收益。
- 核验Agent加在原基线上，检查日期/条件及范围；记录误拦截和字段补全能力。
- 核验加最多一次修正，比较字段完整性、质量和额外调用成本。

核验不能只做删除，否则可能压低召回，也无法修复空负责人。范围过滤、证据裁决、字段补全应在实验结果中分别解释。开发过程中不读取保留测试预测，最终方案固定后再作测试集对照。
